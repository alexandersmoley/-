# assets/inbox — перевалка для медиа с телефона

Сюда падают исходники с телефона. Это перевалочный пункт, а не хранилище.

Отобранные кадры переезжают в `assets/photos/`. Всё остальное удаляется.

## Как это работает

1. Кидаете файлы в эту папку и пушите в ветку.
2. Workflow `media-inbox.yml` подхватывает push и приводит файлы в порядок:
   - `.heic` и `.HEIC` конвертируются в JPEG, оригинал удаляется;
   - длинная сторона ужимается до 2000 px, если была больше;
   - EXIF вычищается целиком, включая GPS — репозиторий публичный;
   - пересобирается `index.json`.
3. Смотрите `index.json`, выбираете нужный кадр.
4. Переносите его в `assets/photos/`:

   ```
   node scripts/promote-media.mjs <файл-в-inbox> <новое-имя>
   ```

   Скрипт кладёт файл в `assets/photos/`, убирает запись из `index.json` и удаляет исходник из inbox.
5. Ненужное удаляете руками и пушите.

## Правила

- Не ссылайтесь на файлы из inbox в `carousels/` и `content/`. Рендер пинит ассеты по пути и sha256; файл из перевалки уедет или исчезнет, и рендер упадёт.
- Всё, что должно жить долго, лежит в `assets/photos/`.
- EXIF снимается автоматически, но **проверяйте сам кадр**: геометку из метаданных система уберёт, а вывеску с адресом в кадре — нет.

## index.json

Машиночитаемая опись содержимого папки. Собирается workflow, руками не редактируется.

Для каждого файла: имя, размеры, вес, sha256, дата коммита и публичная ссылка.

Ссылка ведёт на `raw.githubusercontent.com`, а не на GitHub Pages: Pages в этом репозитории публикует только `instagram-factory/output`, папка `assets/` туда не попадает.
