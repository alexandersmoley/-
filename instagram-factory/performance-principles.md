# Performance principles — Instagram carousels & Reels

Этот документ — обязательный слой поверх `content-strategy.md`, `brand-system.md` и `design-direction.md`. Он не заменяет фирстиль и редакторские правила. Его задача — увеличить вероятность досмотра, дочитывания, сохранений и пересылок без кликбейта и без нейрослопа.

Актуализация: август 2026.

## Что подтверждает исследование

В 2026 Instagram ранжирует разные поверхности по-разному, но для роста особенно важны глубина потребления и пересылки. Для Reels ключевы watch time / retention, replays и sends/shares; для feed-контента важны время на посте, likes, shares/sends, saves и переходы. Reels в среднем сильнее работают на discovery/reach, а карусели — на более глубокое взаимодействие и сохранения.

Практический вывод для `alexsmoley`:

- **Reels = discovery.** Цель — быстро доказать ценность незнакомому человеку и удержать до финала.
- **Carousels = depth.** Цель — заставить листать, дать достаточно конкретики для сохранения и сформулировать мысль, которую хочется отправить коллеге/другу.
- Нельзя оптимизировать только под лайк. Проектируем в первую очередь под **retention, sends/shares, saves**.

## Общие performance-принципы

### 1. Один материал — одна ясная обещанная ценность

До производства сформулировать одним предложением:

> Что человек поймёт / узнает / сможет объяснить после просмотра?

Если обещание нельзя сформулировать без «и ещё», материал распадается на несколько тем.

### 2. First frame / cover — не вступление, а доказательство причины остановиться

Первый экран должен быть понятен без контекста профиля. Он обязан отвечать хотя бы на один триггер:

- конкретный конфликт;
- неожиданный вывод;
- понятная выгода;
- наблюдаемая ошибка;
- сильная позиция;
- открытый информационный разрыв.

Запрещены пустые заходы: «немного мыслей о…», «хочу поговорить о…», «сегодня расскажу…».

### 3. Обещание обложки должно быть выполнено

Нельзя использовать сильный hook, если основная часть повторяет банальности. Каждый следующий экран/эпизод должен либо:

- добавлять новую информацию;
- усиливать доказательство;
- менять масштаб/угол;
- двигать причинно-следственную цепочку.

Повтор одного тезиса разными словами считается потерей retention.

### 4. Проектировать пересылку до написания текста

Перед production ответить:

> Кому и зачем человек может отправить это в DM?

Хорошие share-триггеры для этого блога:

- «это ровно наша рабочая проблема»;
- «вот нормальная формулировка того, что я пытался объяснить»;
- «посмотри, как устроен процесс»;
- «нам надо сделать так же / не делать так»;
- конкретный профессиональный спор или контринтуитивный вывод.

Не вставлять механический CTA «отправь другу», если сам материал не заслуживает пересылки.

### 5. Проектировать сохранение

Save-worthy единица должна содержать хотя бы один reusable asset:

- модель;
- схема;
- чек-лист;
- пошаговый процесс;
- критерии;
- формула;
- классификация;
- конкретный набор примеров.

Если материал только выражает мнение, не притворяться «полезняком» ради сохранений.

### 6. Контент должен работать без знания предыдущих публикаций

Связь с сериалом допустима, но каждый пост/Reel обязан быть самодостаточным. Нельзя начинать с «как я рассказывал вчера», если без вчерашнего поста смысл теряется.

### 7. Никакого algorithm bait

Запрещены искусственные приёмы, которые ухудшают бренд:

- «досмотри до конца» без причины;
- «сохрани, чтобы не потерять» как обязательный шаблон;
- fake urgency;
- обещание секрета без содержания;
- бессмысленные стрелки/swipe cues;
- слишком частые pattern interrupts ради удержания.

Performance достигается структурой и ценностью, а не манипуляцией.

# Carousels

## Роль каруселей

Карусель — формат для последовательного аргумента, кейса, разбора, framework и material-to-save. Её нельзя строить как длинный caption, нарезанный на девять карточек.

## Архитектура сильной карусели

### Slide 1 — stop

Задача: остановить и сформулировать обещание.

Требования:

- один dominant hook;
- считывается примерно за 1–2 секунды;
- не требует чтения мелкого supporting copy;
- хорошо выглядит как thumbnail;
- не раскрывает весь вывод, если информационный разрыв помогает продолжить листание.

### Slide 2 — proof of relevance

Задача: сразу подтвердить, что cover не был кликбейтом.

Лучшие роли второго слайда:

- факт / конкретная ситуация;
- короткая модель;
- контраст «кажется / на деле»;
- начало причинной цепочки;
- обещанный первый полезный элемент.

Не тратить второй слайд на длинное вступление.

### Middle slides — micro-hooks

Каждый слайд должен иметь самостоятельную причину листнуть дальше.

Использовать один из механизмов:

- escalation: проблема становится глубже;
- reveal: появляется новая часть системы;
- contrast: было / стало, ожидание / реальность;
- sequence: следующий обязательный этап;
- evidence: пример подтверждает тезис;
- reframing: меняется интерпретация уже показанного.

### Penultimate / payoff

Перед финалом дать главный reusable asset: схему, принцип, модель, чек-лист, вывод, который можно сохранить отдельно.

### Final slide — resolution

Финал должен закрывать обещание первого слайда, а не просто говорить «подписывайтесь».

Допустимы:

- сильная формулировка вывода;
- consequence / «что это меняет»;
- открытая следующая гипотеза сериала.

CTA только если он естественно продолжает материал.

## Carousel density rules

- один главный смысловой блок на слайд;
- не превращать слайд в страницу статьи;
- supporting copy должен читаться без zoom;
- если слайд требует более 7–10 секунд чтения, проверить возможность разбить его;
- сложная схема лучше длинного абзаца, если она действительно объясняет структуру;
- разнообразие композиций допустимо, но narrative grammar должна быть единой.

## Carousel QA — performance

Перед `approved-for-render` проверить:

- [ ] cover понятен без caption;
- [ ] cover обещает конкретную ценность/конфликт;
- [ ] slide 2 сразу платит по обещанию;
- [ ] ни один middle slide не повторяет предыдущий тезис;
- [ ] у каждого слайда есть функция в narrative;
- [ ] есть хотя бы один send-worthy или save-worthy элемент;
- [ ] финал закрывает hook;
- [ ] материал самодостаточен;
- [ ] нет forced CTA и algorithm bait.

# Reels

## Роль Reels

Reels — discovery-формат. Первые секунды должны работать на человека, который впервые видит `alexsmoley` и ничего не знает про контент-завод.

## Архитектура сильного Reel

### 0–1 sec — first-frame clarity

Первый кадр должен быть уже содержательным. Никаких заставок, логотипов, медленного fade-in или пустой establishing shot.

Если Reel текстовый, первые ключевые слова видны сразу.

### 0–3 sec — hook

Hook должен создать понятный вопрос/конфликт и одновременно дать тему.

Для `alexsmoley` приоритетные типы hook:

- контринтуитивный тезис;
- конкретная ошибка/сбой;
- «X — это не Y»;
- сильное наблюдение из реального процесса;
- до/после архитектуры;
- короткая профессиональная провокация без дешёвого кликбейта.

### 3 sec → payoff — progressive disclosure

Не выдавать весь текст одним экраном. Информация появляется в темпе, соответствующем чтению.

Каждые несколько секунд должен происходить смысловой прогресс:

- новый узел схемы;
- смена тезиса;
- переход от симптома к причине;
- увеличение масштаба;
- доказательство;
- рефрейминг.

Motion должен помогать смыслу. Движение ради движения запрещено.

### Final seconds — payoff / loop

Финал должен дать законченную мысль. Если возможно без ущерба смыслу, строить визуальный/логический loop: последняя композиция или фраза естественно возвращает к первой.

Loop — опция, не обязательный трюк.

## Text-only / motion Reels

Так как текущая система использует Reels без voice-over, соблюдать дополнительно:

- сюжет полностью считывается без звука;
- один экран — одна доминирующая мысль;
- текст не должен меняться быстрее, чем его можно прочитать;
- ключевая фраза остаётся на экране достаточно долго для первого прочтения;
- не использовать длинные абзацы;
- размер и контраст должны работать на телефоне;
- важный текст держать вне зон UI Instagram;
- музыка поддерживает ритм, но Reel не зависит от конкретного аудиотрека;
- визуальная динамика строится через типографику, масштаб, reveal системы, линии/связи и композицию, а не через случайные эффекты.

## Reel QA — performance

Перед `approved-for-render` проверить:

- [ ] first frame содержателен;
- [ ] тема и конфликт ясны за первые ~3 секунды;
- [ ] незнакомый зритель понимает Reel без предыдущих постов;
- [ ] каждая сцена добавляет новую информацию;
- [ ] нет длинной setup-фазы;
- [ ] текст можно физически успеть прочитать;
- [ ] payoff сильнее или конкретнее hook;
- [ ] есть причина отправить Reel другому человеку;
- [ ] при наличии loop он естественный;
- [ ] нет водяных знаков, recycled-platform aesthetics и algorithm bait.

# Metrics loop

После публикации не оценивать материал только по лайкам.

## Reels — приоритет анализа

1. reach / non-follower reach;
2. average watch time / retention, если доступно;
3. completion / replay proxy, если доступно;
4. sends/shares per reach;
5. saves per reach;
6. follows/profile actions после Reel.

## Carousels — приоритет анализа

1. sends/shares per reach;
2. saves per reach;
3. engagement per reach;
4. reach;
5. comments только как качественный сигнал дискуссии.

Сравнивать контент прежде всего с другими публикациями **того же формата и цели**, а не искать универсальный benchmark.

## Production feedback rule

После накопления минимум 5–10 публикаций каждого формата обновлять эти правила на основании собственных данных `alexsmoley`. Внешние best practices — стартовая гипотеза, собственная retention/share/save аналитика имеет приоритет.
