# vc.ru: автоматическое создание черновика

## Цель

После утверждения текста и визуалов Codex должен уметь создать черновик статьи в аккаунте vc.ru автора, заполнить его и вернуть ссылку на черновик. Публикация остаётся ручной и требует отдельного ОК.

Аккаунт автора: `https://vc.ru/id5738265`

## Источник

Для первого пилота:

- статья: `content/vc/autoposting-claude-code.md`;
- публикационный манифест: `content/vc/autoposting-claude-code.publication.json`;
- правила площадки: `channels/vc-ru.md`;
- фирстиль: `brand-system.md` и `design-direction.md`.

## Что должна сделать автоматизация

1. Проверить, что у материала статус `approved-copy` или выше.
2. Проверить, что `publish` равен `false`.
3. Проверить наличие готовой обложки и всех иллюстраций из публикационного манифеста.
4. Открыть авторизованную сессию vc.ru.
5. Создать новую статью в аккаунте автора.
6. Заполнить заголовок и лид из публикационного манифеста.
7. Перенести Markdown статьи в редактор vc.ru с сохранением структуры:
   - H2/H3 → заголовки редактора;
   - обычный Markdown → абзацы;
   - `-` → маркированные списки;
   - цитата со сноской про Instagram → цитатный блок или отдельный абзац;
   - строки со схемами в обратных кавычках → отдельный моноширинный или обычный абзац, если редактор не поддерживает кодовый блок без побочных эффектов.
8. Загрузить обложку.
9. Расставить иллюстрации в местах, заданных манифестом или производственным брифом.
10. Выбрать тему `Личный опыт`, если она доступна автору. Если нет — остановиться и вернуть доступные варианты, не выбирать тему наугад.
11. Сохранить черновик.
12. Вернуть:
   - ссылку на черновик;
   - скриншот/превью;
   - список расхождений между исходным Markdown и редактором vc.ru;
   - предупреждения, если что-то пришлось упростить.
13. Ничего не публиковать.

## Проверки перед сохранением

Автоматически сравнить с исходником:

- заголовок;
- все подзаголовки;
- все абзацы;
- все маркированные списки;
- Telegram-ссылку `https://t.me/a_smoley`;
- сноску про Instagram;
- порядок иллюстраций.

Если потерян хотя бы один содержательный блок, черновик считать неготовым и не переводить в следующий статус.

## Безопасность публикации

Автоматизация не должна нажимать финальную кнопку публикации при любых обстоятельствах, пока публикационный манифест содержит:

```json
"publish": false
```

Даже если пользователь написал в задаче общую формулировку вроде «собери и выложи», для vc.ru первый пилот должен остановиться на черновике. Полная автопубликация включается только отдельным изменением production-контракта после успешных пилотов.

## Статусы

`approved-copy → visuals-ready → vc-draft-created → vc-draft-reviewed → approved-for-publish → published`

Переход `vc-draft-reviewed → approved-for-publish` делает только человек.

## Первый запуск

Для статьи `autoposting-claude-code-vc`:

1. сначала собрать обложку и три иллюстрации по `publication.json` средствами фирменного рендерера;
2. показать визуалы автору;
3. после ОК создать черновик на vc.ru;
4. вернуть ссылку;
5. публикацию не выполнять.

## Что показала проба API (30.08.2026)

Проба `scripts/vc-api-probe.mjs`, запущенная из GitHub Actions (единственная
сетевая среда проекта), три прогона, все read-only — ни одной записи не создано.

Проверенные факты:

- `https://api.vc.ru/v2.31` и `https://api.vc.ru/v2.1` — живые, отвечают JSON;
- `/v1.9` — 404, префикс выведен из эксплуатации;
- `/subsite/subscriptions` — **200** без токена, то есть API реально открыт на чтение;
- `/subsite/me` — **401**, то есть там, где нужна авторизация, API отвечает именно 401;
- `/uploader/upload` — **405** на GET, то есть эндпоинт существует и ждёт POST.
  Загрузка картинок через API доступна;
- `/entry/create`, `/entry/new`, `/entry/draft`, `/entry/drafts`, `/entry`,
  `/entries`, `/writing/create`, `/writing` — **404 на обоих префиксах**.

Вывод: в публичном API есть загрузчик файлов, но нет эндпоинта создания записи
под этими именами. Важно, что API отвечает 401 там, где дело в авторизации, —
значит 404 здесь означает «такого пути нет», а не «нужен токен». Токен эту
картину, скорее всего, не изменит.

Следствие для автоматизации: маршрут «создать черновик через публичный API»
закрыт. Рабочий маршрут — браузерная автоматизация в сессии автора.

Если понадобится вернуться к API: редактор vc.ru при сохранении черновика
куда-то ходит. Найти этот запрос можно в DevTools → Network во время
сохранения черновика; тогда путь станет известен и его можно будет
использовать напрямую. Гадать вслепую больше не нужно — список уже проверенных
путей выше.

## Как это работает сейчас (браузерный маршрут)

Поскольку API создания записи нет, черновик заполняется в браузерной сессии автора.
Скрипты в репозитории, токен нигде не хранится и не нужен.

```
pnpm vc:draft:login     # один раз: открывается браузер, вы логинитесь
pnpm vc:draft           # заполняет черновик из манифеста и статьи
pnpm vc:draft:inspect   # если редактор изменился — карта страницы для починки селекторов
```

Что делает `vc:draft`:

1. Проверяет манифест. Если `publish` не `false` — отказывается запускаться вообще.
   Если визуалы не утверждены — тоже.
2. Проверяет, что сессия жива, по самой странице, а не по наличию файла на диске.
3. Находит поля заголовка и текста по тому, что они сообщают о себе, а не по classname,
   который сломается при первом редизайне.
4. Печатает статью поблочно: заголовки, абзацы, списки, цитату, схемы.
5. Сверяет то, что реально оказалось в редакторе, с тем, что требует контракт: заголовок,
   все подзаголовки, все абзацы, все пункты списков, сноска, ссылка на Telegram.
   Отчёт — `output/vc/vc-draft-report.json`.
6. Если хоть один блок потерялся — называет какой и **не сохраняет черновик**.

Чего скрипт не делает намеренно:

- не публикует и не нажимает «Сохранить» — последний клик за человеком;
- не расставляет картинки: редактор вставляет их по курсору, а место иллюстрации в тексте —
  редакторское решение, которого нет в манифесте. Пути к четырём файлам скрипт печатает.

Сессия лежит в `instagram-factory/.vc-session/` и внесена в `.gitignore`: это учётные данные,
а репозиторий публичный.

### Что ещё не проверено на реальном сайте

Селекторы редактора написаны без доступа к vc.ru — из этой среды он закрыт прокси. Скрипт
поэтому не угадывает: если поле не найдено, он останавливается, пишет карту страницы в
`output/vc/vc-editor-map.json` и ничего не печатает в редактор. Первый запуск покажет, нужна
ли правка; карта — это то, по чему её делать.
