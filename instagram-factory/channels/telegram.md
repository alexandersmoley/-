# Канал: Telegram — @a_smoley

## Роль канала

Telegram — основной короткий/средний текстовый канал Саши. Здесь материал должен ощущаться как сообщение умному знакомому в рабочем чате: быстро к сути, конкретно, разговорно, без лекции и без презентационного языка.

Публичный адрес канала: `https://t.me/a_smoley`.

Telegram не получает копию Instagram-caption или сокращённую vc.ru-статью. Он получает самостоятельную версию из той же утверждённой фактуры.

## Обязательные источники

Перед работой прочитать:

2. `../content-strategy.md`;
3. `../human-topic-rules.md`;

5. уже утверждённые формулировки и факты по теме;

Если есть конфликт между этими файлами, применяется более строгий запрет. Утверждённый пользователем exact copy имеет приоритет над общими советами по структуре.

## Что считать хорошим Telegram-постом

Пост должен быстро отвечать на вопрос: что произошло / что я сделал / что понял / что хочу проверить дальше.

Базовые свойства:

- суть в первых 1–3 абзацах;
- короткие связные абзацы;
- нормальная разговорная речь;
- конкретные действия, сервисы, цифры и наблюдения вместо абстракций;
- допустимы сомнение, раздражение, сухая самоирония;
- не делать из личного опыта «методику», если автор её не заявлял;
- не объяснять очевидное;
- не завершать каждый пост моралью;
- CTA только если он реально нужен.

Не использовать как стилистические костыли:

- конструкции `не X, а Y`;
- «экосистема», «трансформация», «миссия», «новая эра»;
- «показываю работу изнутри», «реальные эксперименты», «закулисье профессии»;
- «конкретная ценность», «авторская оптика», «человеческий слой»;
- «ChatGPT — мозг», «Codex — руки»;
- искусственные афоризмы и рекламные CTA.

## Форматы

### 1. Текстовый пост

`hook/факт → короткое объяснение → наблюдение/результат → что дальше`

Не дробить текст на десятки однофразовых абзацев ради «динамики».

### 2. Пост + карточки

Карточки должны дополнять текст: показывать схему, этапы, сравнение, исходник/результат, цифры или другой визуальный аргумент.

Не дублировать весь пост на карточках.

Если карточки идут серией:

- порядок фиксируется в brief;
- имена файлов должны позволять проверить порядок;
- перед загрузкой проверить все изображения в contact sheet;
- текст карточек должен совпадать с approved copy.

### 3. Пост + одно изображение

Изображение должно быть содержательным: фото, скриншот, схема, документ, результат работы. Декоративная AI-картинка не является default.

### 4. Видео / Reel-reuse

Если в Telegram используется видео из Instagram, подпись переписывается под Telegram. Не переносить Instagram-caption автоматически.

## Редакционный workflow

`master brief → telegram angle → draft → writing QA → fact-check → copy approval → visual package → preview → publish approval → Chrome publish → verification → analytics/learning`

### До copy approval

Claude может свободно:

- предлагать угол;
- сокращать;
- менять структуру;
- предлагать варианты заголовка/первой фразы;
- предлагать карточки.

### После copy approval

Exact copy заморожен.

Нельзя без нового ОК:

- переписывать формулировки;
- добавлять «усиления»;
- менять факты;
- сокращать содержательные куски;
- менять порядок карточек, если он влияет на смысл.

Допустимы только технические изменения, которые не меняют текст: перенос строк интерфейсом, нормализация пробелов, техническое преобразование форматирования.

## Статусы

`idea → brief-review → approved-copy → visuals-ready → telegram-preview → approved-for-publish → published → measured → learned`

Переход в `approved-for-publish` делает только пользователь.

## Публикационный контракт

По умолчанию в source-файле или manifest должно быть:

```yaml
publish: false
```

`publish: false` — абсолютный запрет на отправку сообщения в канал.

Публиковать разрешено только если одновременно выполнено всё:

1. пользователь явно утвердил публикацию;
2. material status = `approved-for-publish`;
3. для Telegram стоит `publish: true`;
4. exact text и assets прошли QA;
5. в Chrome открыт и проверен правильный канал автора.

Фраза пользователя «сделай», «подготовь», «закинь в GitHub», «собери пост» не считается разрешением на публикацию.

Фраза вида «опубликуй в Telegram», «выкладывай в канал», «публикуй все три» — считается разрешением, если понятно, какой именно финальный материал утверждён.

Если есть сомнение, остановиться до клика `Send/Отправить`.

## Публикация через Chrome

Основной браузерный маршрут: авторизованная пользовательская сессия Chrome → Telegram Web.

### Безопасность сессии

- не хранить пароль Telegram в репозитории;
- не хранить коды входа/2FA;
- не копировать Chrome profile в `instagram-factory/`;
- не коммитить cookies, Local Storage, session files или DevTools dumps с токенами;
- не пытаться обходить CAPTCHA/2FA/подтверждения;
- если сессия не авторизована, попросить пользователя войти вручную и продолжить после этого.

### Перед вводом текста

Проверить по видимому UI:

- открыт Telegram Web;
- выбран именно канал Саши, а не личный чат, Saved Messages или другой канал;
- публичный handle/ссылка соответствует `@a_smoley` / `t.me/a_smoley`, если он показан;
- у аккаунта есть право публиковать.

Если идентификация канала неоднозначна — ничего не отправлять.

### Заполнение поста

1. открыть канал;
2. вставить approved text;
3. применить только утверждённое форматирование;
4. если есть media — загрузить точные final assets из manifest;
5. проверить порядок медиа;
6. дождаться окончания загрузки всех файлов;
7. сверить видимый текст с source-файлом;
8. сделать preflight screenshot;
9. только после publish approval нажать отправку;
10. открыть опубликованное сообщение и проверить его ещё раз;
11. сохранить permalink/идентификатор сообщения и screenshot результата.

### Если Telegram изменил форматирование

Если пропал содержательный текст, ссылка, абзац или порядок карточек — результат считать ошибочным.

Если изменились только визуальные переносы строк — это допустимо.

Если rich-text форматирование меняет смысл или читабельность — не отправлять, вернуть preview и описать расхождение.

## QA перед публикацией

Проверить:

- факты подтверждены master brief;
- текст прошёл `writing-contract.md`;
- нет нейрослопа;
- нет копипаста из Instagram/vc без адаптации;
- первая фраза работает без знания предыдущих постов;
- все ссылки корректны;
- все assets финальные;
- порядок карточек корректен;
- нет временных файлов из `assets/inbox/`;
- `publish:true` выставлен именно для Telegram;
- выбран правильный Chrome tab и канал;
- preflight preview соответствует approved copy.

## После публикации

Зафиксировать минимум:

- дата/время;
- URL/permalink сообщения, если доступен;
- формат;
- версия source-файла / commit SHA;
- фактически опубликованные assets;
- расхождения, если Telegram изменил представление.

Дальше по мере доступности фиксировать просмотры, реакции, пересылки, комментарии/обсуждения и другие метрики, которые реально видны в канале. Не выдумывать недоступные показатели.
