# Как я публикую посты в Instagram, не открывая Instagram

Контент-план лежит в Todoist, материалы — в GitHub и Google Drive, публикация идёт через Metricool. Всё это я связал через Claude Code. Ниже — как сейчас работает мой первый нормальный кусок контент-завода.

Я сейчас собираю на своём блоге контент-завод. Пока это звучит громче, чем выглядит: несколько сервисов, папки в GitHub, коннекторы и много мест, где ещё приходится руками говорить «ок».

Но один кусок уже работает. Последний закреп в Instagram я собрал и опубликовал из чата Claude Code. Сам Instagram для этого не открывал. Код руками тоже не писал.

## Что подключил

Сейчас в связке четыре сервиса.

**Todoist** — там лежит контент-план и очередь тем.

**GitHub** — там хранятся правила проекта, брифы, утверждённые тексты и то, что потом идёт в производство.

**Google Drive** — исходные фотографии.

**Metricool** — через него материал уходит в Instagram.

Все четыре подключены к Claude Code как коннекторы. В итоге большую часть работы я веду в одном чате.

## Как проходит один пост

Сначала выбираю тему из контент-плана.

Дальше обсуждаю её в Claude Code: что хочу сказать, какие есть факты, что оставить, что выкинуть. Когда текст утверждён, Claude Code собирает бриф и кладёт его в GitHub.

Бриф — обычный файл. В нём тема, факты, утверждённый текст, правила тона и ссылки на нужные материалы.

Фото лежат отдельно в Google Drive. Для закрепа нужный кадр тоже забирали оттуда.

После этого production уже не сочиняет пост заново. Он получает готовый бриф и собирает из него материал.

Схема сейчас такая:

`Todoist → тема → Claude Code → GitHub → сборка → QA → мой ОК → Metricool → Instagram`

## Зачем тут GitHub

Самая полезная часть всей схемы пока именно эта.

Если держать всё только в чате, правила быстро начинают расползаться. В одном диалоге договорились про Tone of Voice, в другом поменяли формулировку, в третьем забыли, какое фото уже утвердили.

GitHub у меня работает как source of truth. Там остаётся то, что уже решено.

Для каждого материала можно зафиксировать:

- тему;
- факты;
- approved copy;
- Tone of Voice;
- фирстиль;
- референсы;
- нужные фото;
- ограничения;
- статус материала.

Claude Code читает это перед сборкой. Поэтому ему не нужно каждый раз заново объяснять, как выглядит мой пост и каким тоном я пишу.

## Что происходит после брифа

Дальше материал собирается автоматически.

Для карусели это сейчас примерно так:

`brief → structured content → render → QA → preview`

После рендера система проверяет техническую часть. В моём текущем пайплайне есть и проверка утверждённого текста: если макет расходится с approved copy, сборка не должна пройти дальше.

Потом я смотрю превью.

Если всё нормально — даю ОК на публикацию. После этого материал уходит через Metricool в Instagram.

Пока этот последний ОК я оставляю себе. И, скорее всего, ещё долго буду оставлять.

## Что в итоге получилось

Этим способом вышел мой последний закреп.

Для меня здесь интересна не сама автопубликация. Нажать кнопку Publish — не самая тяжёлая часть работы.

Полезнее оказалось связать решения между собой: тема из плана, утверждённый текст, фотографии, правила оформления, сборка и публикация теперь проходят через один понятный маршрут.

И если через неделю я забуду, почему что-то было сделано именно так, решение останется в проекте, а не в старом чате.

## Где пока нужен я

Сейчас я оставил себе несколько точек контроля:

- выбрать тему;
- утвердить текст;
- принять дизайн;
- разрешить публикацию.

Смысл эксперимента для меня как раз в том, чтобы смотреть, какие из этих решений со временем можно безопасно убрать из ручной работы.

Пока я не хочу автоматизировать их просто ради красивой схемы.
