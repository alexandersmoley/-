# Telegram — exact approved copy

Попросил Claude Code взять одну тему и сделать из неё материалы сразу для Instagram, Telegram и vc.ru. Этот пост — один из трёх.

Правило в проекте простое: источник фактов один, тексты разные. Telegram не получает сокращённую статью с vc и не получает подпись из инсты. Из одной фактуры пишутся три отдельных материала.

Самое интересное вылезло на публикации — она везде разная.

Instagram уходит через Metricool по API, это уже работало раньше. С vc.ru я рассчитывал сделать так же и ошибся: публичного эндпоинта для создания записи там нет. Проверил тремя прогонами из GitHub Actions, ничего не создавая: API живой, чтение открыто, загрузчик файлов есть и ждёт POST. А все восемь путей создания записи отвечают 404 на обоих префиксах.

Важная деталь: тот же API честно отвечает 401 там, где дело в токене. Значит 404 — это «такого пути нет», а не «не хватило доступа». Токен ничего бы не изменил, и хорошо, что выяснилось до того, как я его завёл.

Вывод: Instagram по API, vc.ru и Telegram — через браузер в моей сессии.

Дальше про проверки. Макеты рисует рендерер проекта, и сборка падает, если отрисованные слова разошлись с утверждённым текстом, не загрузились нужные шрифты, подпись вылезла из блока или в кадр попал неутверждённый цвет.

Но три дефекта в этом прогоне поймал не рендер, а я глазами, при полностью зелёных проверках. У стрелок наконечники висели отдельно от древка. Черновик на обложке заполнялся снизу вверх, чего не бывает. Баннер аккаунта на узком кропе терял заполнение — то есть всю мысль картинки.

Гейты хорошо ловят технику и вообще не ловят смысл.

Поэтому четыре ОК пока остаются моими: тема, текст, дизайн, публикация. Последний клик в каждом канале жму я.

Пока это первый прогон по новому мультиканальному контракту. Посмотрю на второй-третьей теме, сколько ОК реально нужно.
