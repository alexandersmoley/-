# 0. Контекст перезапуска

Предыдущие публикации были удалены пользователем. Причины:

1. визуал оказался слишком текстовым, однообразным и недостаточно наглядным;
2. содержание ощущалось скучным и поверхностным;
3. обложки плохо работали как самостоятельные объекты в сетке профиля;
4. слишком много «аккуратной типографики» без визуальной фактуры;
5. не чувствовалось, что за аккаунтом стоит конкретный человек с необычным опытом и реальным экспериментом.

**Нельзя использовать предыдущие опубликованные карусели как стандарт качества.** Этот закреп должен стать новой точкой отсчёта.

# 1. Главная идея

Это не карусель «обо мне» в формате резюме.

Это короткая визуальная история:

**кто я → что уже делал → почему мне вообще интересна автоматизация контента → какой эксперимент я запускаю → какой результат считаю успехом**.

Главная человеческая формулировка миссии:

> Я хочу найти модель контент-завода, где хороший контент можно выпускать много и удобно, а от меня в идеале требуется не собирать каждый пост руками, а принимать несколько содержательных решений — буквально пару раз сказать «ок».

Не обещать, что такая система уже существует. Это эксперимент блога.

# 2. Факты об авторе, которые можно использовать

Использовать только эти факты и не расширять их догадками:

- Саша — редактор, хотя это слово уже не полностью описывает его работу.
- Пишет тексты.
- Проектирует интерфейсы.
- Собирает сайты.
- Использует ноукод и понемногу вайбкодит.
- Работает в агентстве заказной разработки.
- Работал/писал для Kaspersky, Сбера, СИБУРа, NtechLab, Черкизово и других больших компаний.
- Параллельно занимается выборами и создаёт агитматериалы, в том числе для кандидатов в президенты.
- Сейчас главный личный эксперимент — построение контент-завода для собственного Instagram.
- Интерес не в том, умеет ли AI написать пост: это уже умеют делать почти все.
- Интерес — в полном производстве: тема → фактура → текст → редактура → дизайн → QA → публикация → аналитика → следующий цикл.
- Критерий результата: много хорошего контента, удобно, предсказуемо, без нейрослопа и без ручной сборки каждой единицы.

Не добавлять достижения, цифры, клиентов, роли или биографические факты, которых нет в этом списке.

# 3. Тон

Нужен живой личный голос, а не B2B-презентация и не «экспертная карусель».

Правила:

- короткие фразы;
- конкретные факты;
- минимум терминологии;
- без пафоса «революционизирую индустрию»;
- без обещаний «полная автоматизация»;
- без «7 шагов», «секретов», «успешного успеха»;
- без слоганов, которых пользователь не утверждал;
- допустима лёгкая самоирония;
- метод появляется из истории, а не заменяет историю.

# 4. Визуальная задача

Ключевое требование: **каждый слайд должен быть наглядным**.

Не собирать карусель как 9 вариаций «заголовок + абзац на цветной плашке».

Для каждого слайда должно быть минимум одно содержательное визуальное ядро:

- исходное фото пользователя;
- коллаж реальных рабочих экранов/интерфейсов;
- названия/типографические маркеры реальных брендов без имитации их логотипов, если ассеты логотипов не разрешены;
- фрагменты допустимых материалов/документов без конфиденциальной информации;
- схема реального процесса;
- объектная метафора, если она напрямую объясняет мысль;
- интерфейсная/редакционная диаграмма;
- крупная цифра/факт, если цифра подтверждена;
- визуальный before/after или «ручное → автоматизированное»;
- фрагменты интерфейса GitHub / renderer / Metricool только если используются реальные разрешённые скриншоты и не раскрывают секреты.

Если реального визуального материала для конкретного слайда нет, использовать **оригинальную editorial-схему**, а не сток и не AI-картинку ради заполнения пространства.

# 5. Глобальная логика композиции

Фирстиль сохраняется, но слайды должны отличаться друг от друга механикой.

Допустимое чередование:

1. photo-led;
2. collage/evidence-led;
3. type + factual objects;
4. interface-led;
5. system diagram;
6. contrast / before-after;
7. editorial statement;
8. process map;
9. strong closing image + short line.

Нельзя делать одну и ту же сетку девять раз.

При этом серия должна ощущаться единой за счёт:

- Inter / Cormorant Garamond;
- фирменного blue / cream / black;
- общей системы полей;
- одинаковой типографической дисциплины;
- повторяемых тонких линий/сеточных привязок;
- характера photo crop и редакционной композиции.

# 6. Обложка — отдельная задача

Обложка должна работать в профиле с первого взгляда.

## Требования

- ключевой смысл считывается в thumbnail;
- не больше 5–8 слов в главном headline;
- лицо/фото/объект — крупно;
- headline — крупный, контрастный, без мелкого поясняющего текста;
- никаких мелких списков брендов на обложке;
- визуальный фокус один;
- в thumbnail должно быть понятно: это пост про человека + эксперимент, а не generic AI-карусель;
- обложка не должна быть похожа на предыдущие text-only карточки.

## Сделать 3 реально разных варианта обложки

### A. Photo-led
Большое исходное фото Саши + короткий headline.

Рабочий headline:
**«Строю контент-завод на себе»**

Допустимый маленький secondary:
**«Привет, я Саша»**

### B. Mission-led
Сильная наглядная схема/конвейер + фото как второй слой.

Headline:
**«Хочу делать контент парой “ОК”»**

Мелко, только если читается:
**«Проверяю, возможно ли это без нейрослопа»**

### C. Human + system
Крупный портрет/фрагмент рабочего пространства + визуальная цепочка вокруг.

Headline:
**«Редактор. Теперь строю завод»**

Не добавлять слово `AI` на обложку только ради узнаваемости темы.

Codex должен отрендерить все 3 варианта первой карточки и отдельный thumbnail-sheet на масштабе профиля. Полную карусель собирать на базе наиболее сильного направления, но сохранить остальные две обложки для сравнения.

# 7. Содержание карусели — exact editorial structure

Ниже — утверждённая смысловая структура. Точные формулировки можно **редакторски поджать внутри смысла**, но нельзя добавлять новые факты. Перед финальным render сохранить финальный copy в structured source и не менять его во время верстки.

## Slide 1 — COVER

Один из трёх вариантов выше.

Цель: остановить взгляд и дать понять, что перед нами конкретный человек с конкретным экспериментом.

## Slide 2 — «Я редактор. Но давно не только пишу тексты»

Смысл:

**Я редактор, хотя это слово уже плохо описывает всю мою работу. Пишу тексты, проектирую интерфейсы, собираю сайты, использую ноукод и понемногу вайбкожу.**

Визуал:

- не просто текст;
- editorial collage из 3–4 визуальных фрагментов: текстовый документ, интерфейс/wireframe, сайт/browser, код/ноукод;
- если нет разрешённых реальных скриншотов — создать чистые абстрактные wireframe-фрагменты без выдуманных брендов и данных.

Главный акцент: диапазон работы.

## Slide 3 — «Где я успел поработать»

Смысл:

**Kaspersky / Сбер / СИБУР / NtechLab / Черкизово**

И короткая строка:

**Параллельно занимаюсь выборами и создаю агитматериалы — в том числе для кандидатов в президенты.**

Визуал:

- сделать это как редакционную «стену фактов» / clipping board / typographic evidence;
- названия компаний должны быть частью композиции, не мелким списком;
- не использовать логотипы, если нет отдельного разрешённого ассета;
- политический опыт визуально отделить вторым слоем/документной метафорой, не использовать партийную символику без необходимости.

Слайд должен давать ощущение диапазона: корпоративные коммуникации ↔ выборы.

## Slide 4 — «Почему я вообще полез в это»

Смысл:

**Все уже умеют попросить ChatGPT написать пост. Мне интереснее другое: можно ли автоматизировать производство целиком, а не только черновик текста.**

Визуал:

- слева/сверху очень простая схема `промпт → текст`;
- рядом/ниже она визуально «ломается» или оказывается маленькой частью большой цепочки;
- это должен быть графический reveal, а не абзац.

## Slide 5 — «Вот мой эксперимент»

Смысл:

**Я строю первый контент-завод на собственном Instagram.**

Далее крупно:

**Хочу найти наиболее рабочую модель: чтобы хороший контент выходил много, удобно и предсказуемо.**

Визуал:

- здесь впервые показать «машину» целиком;
- не индустриальный клипарт, а editorial process map;
- можно использовать реальные названия текущих слоёв: идея / фактура / текст / дизайн / QA / публикация / аналитика.

## Slide 6 — «Идеальный интерфейс для меня — пара “ОК”»

Смысл:

**Не хочу руками собирать каждый пост. В идеале система сама проходит рутину, а я подключаюсь там, где нужно принять решение: тема, смысл, финальный вариант.**

Визуал:

- наглядная before/after композиция;
- слева хаотичная ручная цепочка с большим количеством касаний;
- справа короткий путь с 2–3 крупными human approval nodes `ОК`;
- не обещать, что это уже достигнуто;
- подпись вроде `цель эксперимента`, чтобы не выдавать target state за reality.

Это один из ключевых слайдов карусели.

## Slide 7 — «Но есть условие»

Смысл:

Крупно:

**Много ≠ хорошо**

Ниже:

**Если автоматизация просто ускоряет выпуск посредственного контента, такой завод мне не нужен.**

Визуал:

- наглядный контраст «конвейер одинаковых карточек» vs «разные полноценные форматы»;
- можно использовать метку `БРАК` только как содержательную часть идеи, не как постоянный декоративный элемент;
- показать визуально, что разнообразие форматов важнее однотипного потока.

## Slide 8 — «Что я буду проверять здесь»

Смысл — не список инструментов, а реальные вопросы:

- как искать темы;
- как собирать фактуру;
- как писать и редактировать;
- как делать дизайн;
- как переиспользовать один смысл в разных форматах;
- как публиковать;
- как возвращать аналитику обратно в следующий цикл.

Визуал:

- не 7 буллетов;
- сделать как маршрут/панель процесса с 7 узлами;
- каждый узел должен отличаться визуально, но не превращаться в набор разноцветных иконок;
- можно использовать мини-фрагменты реальных интерфейсов/документов, если они безопасны.

## Slide 9 — финал

Крупный финальный тезис:

**Много. Удобно. Не стыдно публиковать.**

Ниже:

**Если получится на собственном блоге — следующим шагом буду собирать такие системы для брендов.**

Визуал:

- сильный финальный editorial frame;
- возможно фото + схематичная линия процесса, уходящая за край;
- минимум текста;
- ощущение начала эксперимента, а не продажи услуги здесь и сейчас.

# 8. Caption — рабочая версия

Привет, я Саша. Я редактор, хотя это слово уже не очень точно описывает мою работу.

Пишу тексты, проектирую интерфейсы, собираю сайты, использую ноукод и понемногу вайбкожу. Работал с Kaspersky, Сбером, СИБУРом, NtechLab, Черкизово и другими большими компаниями. Параллельно занимаюсь выборами и создаю агитматериалы — в том числе для кандидатов в президенты.

Сейчас мой главный эксперимент — контент-завод для собственного блога.

Не в смысле «пусть ChatGPT пишет за меня посты». Это как раз самая простая часть.

Мне интересно найти такую модель производства, где система помогает искать темы, собирать фактуру, делать текст и дизайн, проверять результат, публиковать и возвращать аналитику в следующий цикл. А я постепенно перестаю руками таскать материал между всеми этими этапами и подключаюсь только там, где действительно нужно принять решение.

В идеале интерфейс такого завода для меня выглядит почти смешно: несколько раз посмотреть на результат и сказать «ок».

Но есть условие: на выходе должен оставаться контент, который я сам готов публиковать. Не больше нейрослопа, а больше нормальных материалов.

Здесь и буду проверять, насколько это вообще возможно.

# 10. Дизайн: что должно стать лучше относительно прошлой версии

Обязательные улучшения:

1. **Больше изображений и фактуры.** Минимум 6 из 9 слайдов должны иметь содержательный визуальный слой помимо текста.
2. **Разные композиции.** Не повторять один template family на всех слайдах.
3. **Больше доказательности.** Факты должны выглядеть как факты: имена брендов, схема работы, реальный диапазон задач.
4. **Меньше абзацев.** По возможности один сильный тезис + визуальное объяснение.
5. **Наглядность важнее декоративности.** Любой элемент должен объяснять факт, процесс, контраст или характер автора.
6. **Thumbnail-first cover.** Проверить реальное уменьшенное превью.
7. **Не делать индустриальный cosplay.** Конвейеры/штампы/маркировка допустимы только если помогают конкретной мысли.
8. **Не делать AI aesthetic.** Никаких роботов, светящихся нейросетей, 3D-мозгов, sparkles, чат-пузырей ради темы AI.
9. **Не делать корпоративную презентацию.** Это Instagram живого человека, а не pitch deck продукта.
10. **Не делать «премиальный минимализм» ценой пустоты.** Если слайд выглядит красиво, но ничего не показывает, он не проходит QA.

# 11. Performance / narrative QA

## Cover

- читается в thumbnail;
- hook понятен без caption;
- визуальный объект заметен быстрее текста второго уровня;
- нет длинного subtitle;
- не похож на предыдущую обложку только заменой слов.

## Carousel

- slide 2 сразу отвечает «кто это?»;
- slide 3 даёт доказательство опыта;
- slide 4 создаёт конфликт/проблему;
- slide 5 раскрывает эксперимент;
- slide 6 показывает target state наглядно;
- slide 7 добавляет важное ограничение, а не повторяет миссию;
- slide 8 показывает, что именно будет происходить в блоге;
- slide 9 даёт короткий запоминающийся payoff;
- каждый слайд добавляет новую информацию;
- нет двух соседних слайдов с одинаковой композицией;
- нет text-wall;
- минимум 6 слайдов visual-first/evidence-first;
- сюжет понятен человеку, который впервые видит аккаунт.

# 12. Технический QA

- 1080×1440 каждый слайд;
- safe zone минимум 120 px для ключевого текста;
- Inter / Cormorant Garamond только по утверждённым ролям;
- display line-height 0.94, body 1.24;
- неразрывные пробелы по русской типографике;
- exact final copy после редакторского freeze;
- никакого invented copy после freeze;
- никакого изменения внешности на фото;
- все внешние картинки/скриншоты имеют понятный источник и допустимое использование;
- contact sheet;
- отдельный thumbnail sheet трёх cover-концепций;
- PNG всех слайдов;
- structured source;
- QA report.

# 13. Definition of Done

Production считается готовым к показу пользователю только если:

- есть 3 разные обложки;
- одна полная карусель из 9 слайдов;
- содержание не выглядит как резюме или AI-гайд;
- минимум 6 слайдов визуально наглядны;
- thumbnail обложки читается;
- в карусели виден конкретный человек, конкретный опыт и конкретная миссия;
- миссия «много + удобно + несколько осознанных ОК + без слопа» понятна без чтения caption;
- карусель визуально разнообразна, но остаётся в одной brand system;
- QA зелёный;
