# Master brief: автопостинг без открытия Instagram

## Исходник

Статья описывает период, когда завод работал на ChatGPT и Codex. Это решение автора: материал остаётся снимком того этапа, а не переписывается под текущий стек.

Утверждённый текст лежит в `content/vc/autoposting-claude-code.md` со статусом `approved-copy`. Он и есть источник фактуры для этой статьи.

## Соотношение с Reels

Рил `autoposting-setup-reel` описывает более поздний вариант того же завода — на Claude Code с четырьмя коннекторами: Metricool, Todoist, GitHub и Google Drive. Это отдельный материал про другой этап, а не источник для этой статьи.

Из этого следует правило для production: **не приводить статью к стеку рила**. Замена ChatGPT и Codex на Claude Code сделает текст неверным для описанного в нём периода.

## Что подтверждено утверждённым текстом статьи

- работа над темой и текстом шла в ChatGPT;
- очередь тем лежала в Todoist;
- GitHub хранил brief, approved copy и правила проекта;
- Google Drive хранил исходники;
- техническое производство выполнял Codex;
- публикацию выполнял Metricool;
- закреп был собран и опубликован этим способом;
- автор не писал код руками;
- публикация не происходила без отдельного approval.

## Что важно не придумывать

- экономию времени, процентов или денег;
- количество постов, которое система выпускает автоматически;
- полную автономность;
- отсутствие ошибок;
- универсальность схемы для любого автора или бренда;
- функции Metricool / Claude Code / Instagram, которые не подтверждены текущей системой или свежей документацией.

## Сюжет статьи

### 1. Заход

Реальный результат: закреп в Instagram был собран и опубликован через этот workflow. Автор работал из чата ChatGPT, производство выполнял Codex, руками код автор не писал.

### 2. Что хотелось убрать

Не «создание контента целиком», а повторяющиеся переходы между сервисами и техническую часть после того, как тема и текст уже утверждены.

Важно сформулировать без риторики «не X, а Y».

### 3. Роли сервисов

- ChatGPT — контент-план, работа с темой, текст и редактура;
- Todoist — очередь тем;
- GitHub — source of truth для brief, approved copy и правил;
- Google Drive — исходники;
- Codex — техническое производство;
- Metricool — публикационный слой.

### 4. Как проходит один материал

`план → тема → обсуждение в ChatGPT → brief в GitHub → assets из Drive → сборка Codex / QA → approval → Metricool → Instagram`

### 5. Зачем brief

Brief — контракт между редакционной работой и production.

Он фиксирует:
- тему;
- факты;
- approved copy;
- правила тона;
- нужные assets;
- ограничения.

Production не должен заново «придумывать пост».

### 6. Что проверяется перед публикацией

- structured content;
- соответствие approved copy;
- visual / technical QA;
- отдельный human approval.

### 7. Что получилось на практике

Закреп был опубликован через этот workflow. Это первый доказанный кейс внутри личного контент-завода.

Не делать из этого доказательство масштабируемости.

### 8. Что дальше

Следующий эксперимент — вынести ту же фактуру в vc.ru и проверить уже мультиканальность: один master brief → разные самостоятельные форматы.

Сам материал на vc.ru одновременно является этим экспериментом.
