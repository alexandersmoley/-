# Master brief: автопостинг без открытия Instagram

## Исходник

Первая статья для vc.ru строится на уже готовом Reels `autoposting-setup-reel`.

Главный исходный тезис:

> Чтобы выложить пост, я не открываю Instagram. Всё делается в чате Claude Code.

Статья должна расширить этот опыт: показать, какие сервисы подключены, зачем нужен GitHub, что такое brief, где происходит сборка и почему публикация всё равно остаётся за approval gate.

## Что подтверждено исходным Reels

- используются четыре внешних сервиса: Metricool, Todoist, GitHub и Google Drive;
- все они подключены к Claude Code как коннекторы;
- Metricool выполняет публикацию в Instagram;
- Todoist хранит план тем;
- GitHub хранит brief, approved copy, правила тона и материалы проекта;
- Google Drive хранит исходные фотографии;
- тема обсуждается в Claude Code;
- Claude Code формирует brief и кладёт его в GitHub;
- из brief собирается карусель;
- production проверяет совпадение утверждённого текста с рендером;
- реальный закреп был опубликован этим способом;
- автор не писал код руками;
- публикация не должна происходить без отдельного approval.

## Что важно не придумывать

- экономию времени, процентов или денег;
- количество постов, которое система выпускает автоматически;
- полную автономность;
- отсутствие ошибок;
- универсальность схемы для любого автора или бренда;
- функции Metricool / Claude Code / Instagram, которые не подтверждены текущей системой или свежей документацией.

Контент-план лежит в Todoist, материалы — в GitHub и Google Drive, публикация идёт через Metricool. В статье разбираю, как связал это в один процесс и где всё ещё нужен мой ОК.

## Сюжет статьи

### 1. Заход

Реальный результат: закреп в Instagram был собран и опубликован через этот workflow. Автор работал из чата Claude Code и руками код не писал.

### 2. Что хотелось убрать

Не «создание контента целиком», а повторяющиеся переходы между сервисами и техническую часть после того, как тема и текст уже утверждены.

Важно сформулировать без риторики «не X, а Y».

### 3. Четыре сервиса

- Todoist — очередь тем / контент-план;
- GitHub — source of truth для brief, approved copy и правил;
- Google Drive — исходные фото;
- Metricool — публикационный слой.

Claude Code связывает эту работу в чате и production-команды.

### 4. Как проходит один материал

`план → тема → обсуждение в Claude Code → brief в GitHub → assets из Drive → сборка / QA → approval → Metricool → Instagram`

### 5. Зачем brief

Brief — контракт между редакционной работой и production.

Он фиксирует:
- тему;
- факты;
- approved copy;
- правила тона;
- нужные assets;
- ограничения.

Production не должен заново «придумывать пост».

### 6. Что проверяется перед публикацией

- structured content;
- соответствие approved copy;
- visual / technical QA;
- отдельный human approval.

### 7. Что получилось на практике

Закреп был опубликован через этот workflow. Это первый доказанный кейс внутри личного контент-завода.

Не делать из этого доказательство масштабируемости.

### 8. Что дальше

Следующий эксперимент — вынести ту же фактуру в vc.ru и проверить уже мультиканальность: один master brief → разные самостоятельные форматы.

Сам материал на vc.ru одновременно является этим экспериментом.
