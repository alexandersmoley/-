# Content handoff: ChatGPT → Codex → Canva → Publishing

## Принцип

Текст поста передаётся Codex не через копипаст в чат, а как структурированный Markdown-файл в `instagram-factory/posts/`.

Одна единица контента = один файл.

Пример имени:

`2026-09-01-pinned-intro.md`

## Обязательные поля

```yaml
---
id: pinned-intro
platform: instagram
format: single-post
status: draft
publish_at:
canva_template:
visual_asset: MAHTX_B6J9k
---
```

После front matter идут секции:

```md
# Cover
Привет, я Саша Смолей

# Caption
Полный утверждённый текст подписи поста.

# Visual notes
Только конкретные инструкции для этого поста. Если секция пустая, Codex не добавляет ничего от себя.

# Production notes
Технические замечания: нужный мастер-шаблон, количество карточек, required assets и т. п.
```

## Статусы

- `draft` — идея/черновик, Codex не производит;
- `review` — текст обсуждается, Codex не производит;
- `approved-for-production` — текст утверждён, Codex может собирать визуал в Canva;
- `design-review` — дизайн собран и ждёт проверки;
- `approved-for-publishing` — можно ставить в очередь публикации;
- `published` — опубликовано;
- `measured` — метрики собраны.

## Что делает ChatGPT

1. Штурмит идею вместе с пользователем.
2. Готовит текст.
3. После явного утверждения пользователя сохраняет/обновляет файл поста в GitHub.
4. Меняет статус на `approved-for-production` только после approval текста.

## Что делает Codex

1. Читает `brand-system.md`, соответствующий design brief и файл поста.
2. Работает только с утверждёнными полями.
3. Подставляет текст и assets в Canva.
4. Не переписывает caption.
5. Не добавляет новый copy в визуал.
6. После сборки меняет статус/отмечает handoff как `design-review` и возвращает ссылку на Canva.

## Что будет автоматизировано позже

После проверки MVP GitHub может быть заменён/дополнен Airtable как интерфейс контент-бэклога. Схема данных должна остаться той же, чтобы Codex и автоматизация работали независимо от UI.
