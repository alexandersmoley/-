# CLAUDE.md — входная инструкция для Claude / Claude Code

Ты работаешь над производственной системой личного Instagram `alexsmoley` и связанных каналов автора.

## 0. Главная цель

Блог — личный сериал о работе Саши Смолея, его экспериментах с AI и обычной жизни.

Сквозная профессиональная линия — как AI меняет работу с контентом и можно ли постепенно собрать удобный контент-завод.

Контент-завод не является темой каждого поста. Главный герой — Саша.

Текущий мультиканальный контур проекта: Instagram `alexsmoley` + Telegram `@a_smoley` + vc.ru `id5738265`.

## 2. Writing contract

Все новые посты, карусели, Reels, Stories, подписи, заголовки и briefs проходят `writing-contract.md`.

Базовый тон — инфостиль: коротко, конкретно, без пафоса, маркетинговой воды, псевдоафоризмов и искусственной рублености.

История не означает литературщину. Факты и действия важнее красивой подачи.

## 3. Истории вместо рубрик

Новая единица контента должна начинаться с реальной истории или реального наблюдения.

Три основных источника:

- **работа** — редакторские задачи, интерфейсы, сайты, ноукод, согласования, рабочие решения;
- **эксперименты** — конкретные тесты AI, автоматизации и контент-завода;
- **жизнь** — семья, город, поездки, зал, бытовые моменты и другие реальные события.

Не нужно искусственно связывать все три линии между собой.

Личная история может остаться личной.

Рабочая история может не содержать AI.

AI-эксперимент может не упоминать термин `контент-завод`.

## 4. Контент-план — не приказ

Todoist хранит гипотезы и story slots, а не обязательные темы.

Если запланированная тема не получила реальной фактуры, её нельзя производить только потому, что она стоит в плане.

Если появляется более сильная история, она заменяет слабую запланированную тему.

Перед production спроси:

1. Что реально произошло?
2. Какая конкретная фактура есть?
3. Что в этом материале принадлежит именно опыту автора?
4. Есть ли смысл рассказывать это сейчас?
5. Не натянут ли AI или контент-завод искусственно?

Если реальной истории нет — останови production.

## 5. Структуры

Для рабочей истории:

`эпизод → действие/решение → результат или наблюдение`

Для эксперимента:

`задача → что попробовал → результат → что меняю дальше`

Для личной истории:

`контекст → история`

Профессиональный вывод для личного поста не обязателен.

## 6. Негатив не является стратегией

Не строить блог преимущественно на провалах и разочарованиях.

Историю могут двигать:

- неожиданность;
- выбор;
- изменение;
- хороший результат;
- сложность;
- конкретное решение;
- противоречие;
- новая возможность;
- живая деталь.

Не искать негативный конфликт специально.

## 7. Контент-завод

Контент-завод — длинная линия проекта.

Публичная задача: проверить, насколько производство хорошего контента можно сделать проще и удобнее с помощью AI и автоматизации.

Не объясняй всю архитектуру в каждом посте.

Текущая рабочая формулировка профиля:

**Писал для Kaspersky, Сбера и кандидатов в президенты. Теперь строю контент-завод**

Не усиливать и не расширять эту формулировку без решения пользователя.

## 8. Факты

- Не выдумывать личные эпизоды, рабочие кейсы, диалоги, цифры или результаты.
- Клиентский материал называть `писал для`, если другая роль не подтверждена.
- Не использовать NDA/confidential фактуру.
- Не превращать намерение в готовый результат.
- Не создавать fake evidence для визуала.

## 9. Разделение ролей

### Claude / ChatGPT в чате

Редакционная работа:
- заметить историю;
- проверить фактуру;
- выбрать угол;
- написать и отредактировать текст;
- подготовить art direction;
- сохранить approved brief.

### Claude Code / Codex

Production:
- прочитать approved brief;
- собрать structured content;
- при необходимости изменить renderer/layout;
- отрендерить;
- сделать QA;
- подготовить contact sheet/thumbnail preview;
- сохранить artifacts.

Кодовый агент не меняет утверждённый смысл или copy ради макета.

### Browser / Chrome adapter

Публикационный слой:
- работает только с уже утверждёнными channel packages и final assets;
- использует авторизованную пользовательскую сессию Chrome;
- проверяет правильный домен, аккаунт и канал до любого финального действия;
- готовит browser preflight/preview;
- не хранит пароли, cookies, session tokens и 2FA в GitHub;
- не публикует при `publish:false`;
- после явного publish approval публикует каналы последовательно и проверяет результат каждого;
- возвращает published URL/permalink и фиксирует частичные сбои без дублей.

Подробно: `channels/multichannel-chrome-publishing.md`.

## 10. Визуальный контракт

Визуал должен показывать историю.

Приоритет:
- реальные фото;
- реальные скриншоты;
- интерфейсы;
- документы;
- фрагменты рабочего процесса;
- предметы и места из истории;
- схемы, если они реально что-то объясняют;
- коллажи из содержательной фактуры.

Не заменять фактуру декоративным AI-языком.

Обложки должны читаться в thumbnail, иметь один сильный фокус и различаться по композиции.

## 11. Approval gates

`idea` → `brief-review` → `approved-for-render` → `rendered` → `design-review` → `approved-for-publish` → `scheduled/published` → `measured` → `learned`

Без явного approval пользователя статус не повышать.

Для мультиканальной темы approval ведётся отдельно по каналам. `publish:true` у Telegram не даёт права публиковать Instagram или vc.ru. Общий ОК на все каналы допустим только если пользователь видел финальные версии и прямо сказал публиковать все.

## 12. Первый запуск нового агента

При первом входе:

1. ничего не менять;
2. изучить source-of-truth файлы;
3. проверить `content/`, `renderer/`, `visual-references/`, `output/`;
4. изучить `channels/`, если задача связана с Telegram/vc.ru/мультиканальной публикацией;
5. показать карту проекта и противоречия;
6. остановиться до подтверждения.

## 13. Критерий успеха

Успех проекта — не максимум автоматизации.

Успех = хороший контент + регулярность + меньше рутины + понятные человеческие решения + воспроизводимый результат.

Но качество отдельного поста начинается не с pipeline, а с истории, которую действительно стоит рассказать.

Для мультиканального workflow дополнительный критерий: одна фактура должна превращаться в самостоятельные материалы для Instagram, Telegram и vc.ru без повторной работы с нуля, без самовольных смысловых правок и без дублей при публикации.
